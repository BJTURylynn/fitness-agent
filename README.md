# 练记 · Fitness Agent

中文力量训练助手。零运行时 npm 依赖，Node.js 22.13+，电脑和手机浏览器自适应。

```sh
git clone https://github.com/BJTURylynn/fitness-agent.git
cd fitness-agent
```

## 运行

需要 Node.js 22.13 或更新版本。克隆仓库后，进入包含 `package.json` 的仓库根目录。运行、构建和测试均使用 Node.js 内置功能，无需先安装 npm 依赖；Windows PowerShell、macOS 和 Linux 都可执行：

```sh
node scripts/build.mjs
node scripts/dev.mjs
```

打开 http://127.0.0.1:4173 。本地服务仅监听本机，按 Ctrl+C 停止；可用 `PORT` 环境变量调整端口。

如果已安装 npm，也可执行 `npm start` 或 `npm run dev`，两者都会先自动构建，再启动本地服务。直接运行 `node scripts/dev.mjs` 时，需先构建。

Windows 也可直接双击仓库根目录的 `start.cmd`，它会构建并启动应用，不依赖固定磁盘路径。

首次启动会自动创建仓库目录同级的 `work/` 目录，并应用已提交的数据库迁移。未设置模型服务时，动作查询、训练记录、月历、身体档案和本地规则分析仍可使用；AI 功能需完成下方模型配置。

## 功能

- 六大部位按钮与细分训练侧重筛选；搜索中英文动作，查看步骤、错误提醒与参考来源。
- 每个动作记录逐组重量、次数、设定休息秒数、RPE、热身/正式组与完成状态；支持休息计时。
- 按日期保存训练、编辑历史记录；训练量只计算已完成的非热身组。
- 训练月历支持切换/跳转月份、回到今天，按日显示训练时长与部位；点击日期查看动作、逐组表现或补录训练。
- 点击日历中的训练标签直接打开对应的训练日志；同一天的多次训练分别显示、分别进入。再次打开正在编辑的同一条训练时会保留编辑草稿。
- 每次训练可填写北京时间的开始时间和总时长（时:分:秒），同一天可记录多次训练。月历汇总训练天数、时长和正式组。
- 身体档案记录身高、训练目标、经验，按日期记录体重与体脂率，查看变化趋势。
- AI 动作讲解、训练复盘与教练问答，可接入 AiHubMix 或其他兼容的模型服务。
- JSON 备份导出与导入。本地规则分析始终明确标注，不冒充模型回答。

## 模型配置

打开应用中的“模型设置”，填写 Base URL、模型 ID 和 API Key，即可接入支持 OpenAI Chat Completions 协议的服务。

- “测试连接”只发送一条简短验证消息，不发送训练或身体记录。
- “保存并使用”先实际验证连接，成功后才替换当前配置；失败会保留原有可用配置。
- 已保存的 Key 不回显。保持相同 API 地址时可留空沿用；更改地址后必须重新填写 Key。
- “恢复默认配置”会移除当前用户的自定义配置，并使用站点默认模型。

线上配置按登录用户隔离，API Key 使用 AES-GCM 加密后写入 D1；加密主密钥位于服务端环境变量 MODEL_CONFIG_ENCRYPTION_KEY。公网 HTTPS Base URL 才能用于云端请求，系统不接受 localhost、内网地址、嵌入账号或查询参数的地址。

本地版使用 Node.js 内置 SQLite。私有文件位于仓库目录同级的 `work/` 中：

- `model-settings.sqlite`：加密后的自定义模型配置。
- `model-runtime.json`：首次启动自动生成的加密主密钥。
- `local-env.json`：可选的站点默认模型配置，其中的 API Key 为明文，必须作为私有文件保管。

这些文件不属于源码，不应上传 GitHub。迁移本地模型设置时，应在停止服务后，将数据库与对应的主密钥一起安全备份、一起迁移；仅克隆仓库不会恢复原有模型设置。主密钥若遗失或更换，原有自定义密钥需要重新保存。

通常直接使用应用中的“模型设置”即可。站点默认模型也可由进程环境变量 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL` 配置，变量名参见 `.env.example`。程序不会自动读取 `.env`；将示例复制成 `.env` 本身不会生效。环境变量优先于 `work/local-env.json`。

例如，调整本地端口后启动：

```powershell
# Windows PowerShell
$env:PORT = '4174'
node scripts/dev.mjs
```

```sh
# macOS / Linux
PORT=4174 node scripts/dev.mjs
```

可选命令 `node scripts/configure-local.mjs` 从标准输入接收一行 JSON（字段仅限上述三个 `LLM_*` 变量），并将其保存到私有的 `work/local-env.json`。交互终端输入会隐藏；请输入完整 JSON 后按 Enter。不要将含密钥的 JSON 写入源码或共享终端记录。

## 数据与隐私

训练和身体记录保存在当前浏览器的 localStorage，不自动同步到云端或其他设备。使用 AI 按钮时会将当前请求所需的身体档案、训练与部分历史记录发送给当前选中的模型服务；不会发送到检索服务。聊天记录仅在当前界面内存中使用，服务端不持久保存。

清理浏览器数据、更换浏览器、端口或域名后，本地记录不会自动迁移；克隆仓库也不会同步这些记录。请定期使用 JSON 导出备份，再在新设备导入。训练备份可能包含身体与训练信息，应私下保管。私有部署由 Sites 控制访问范围。

## 记录约定

- 哑铃重量按一只哑铃的标称重量记录；杠铃按含杆总重记录。自重动作填 0，仅记录额外负重，次数照常记录。负重口径需保持一致。
- 重量×次数是外部负重的记录指标，不能跨不同动作、器械直接比较，也不等于热量或完整训练刺激。
- 休息时间是记录的设定值，计时器帮助执行；应用不自动检测真实组间休息。
- RPE 为主观用力感 1–10；留空即未知。
- 开始时间与训练时长均可留空，时长最长 24 小时。时长按实际填写汇总，包含组间休息；应用不会根据组数推算。旧记录保留为“未记时”，可通过编辑补录，旧 JSON 备份仍可导入。
- 上/中/下胸等为训练侧重标签，并非三个可完全隔离的独立肌肉。腹部训练侧重不代表局部减脂。
- 数字记录无法判断实际动作姿势；出现锐痛或持续不适应停止相关动作并寻求专业评估。

## 检查与发布

```powershell
node --test tests/*.test.mjs
node scripts/build.mjs
node scripts/validate-artifact.mjs
```

测试使用虚构模型密钥与临时数据库，不需要配置或调用真实模型服务。

日常运行无需依赖安装。仅在维护数据库 schema、重新生成迁移时，安装已锁定的开发依赖：

```sh
pnpm install --frozen-lockfile
pnpm db:generate
```

`public/` 为前端源码，`server-api.js` 为模型服务端接口，`worker/index.js` 为部署入口，构建后 `dist/server/index.js` 是自包含的 Worker ES module。`db/schema.ts`、`drizzle.config.ts` 与 `drizzle/` 保留数据库结构和迁移历史；本地启动会应用已有迁移。

`dist/` 和 `node_modules/` 可从源码重新生成，无需提交。源码中的 `.openai/hosting.json` 仅保存当前 Sites 站点标识，不含运行密钥；克隆后本地运行无需修改它，部署到新站点时应由对应部署流程配置新的站点身份及服务端密钥。GitHub 用于保存源码，不会自动部署这个带服务端接口的应用。
